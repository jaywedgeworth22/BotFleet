## What this PR fixes

Jay opened the BotFleet settings panel on 2026-09-23 and reported five gaps in the Engines + Usage surface.  This PR closes all five.

1. **Per-bot usage rows were too terse.**  Each row showed a single dollar total with no model, no per-session tokens in/out, no per-session cached, no $/turn, no cumulative.  A reader could not tell whether a $4 bot ran one Opus call or forty MiniMax turns.  Now each row is a collapsible `<UsageRow>` disclosure that drops a per-session table (timestamp, model, tokens in/out, cached, $/turn, cumulative tokens, cumulative cost).  "Expand all / Collapse all" header button.

2. **MiniMax pricing breakdown was wrong-shaped.**  BotFleet was showing MiniMax's PAYG API rates as the only pricing reference even though Jay pays for a Token Plan subscription — not API.  Now the MiniMax row shows `Subscription + API · $55.00/mo` with an `Included` pill for the per-1k rate column.  Subscription-only engines (Claude, Codex, Cursor) render `Subscription · $X/mo` + `Included`.  The API rates are surfaced only inside the new "what-if API" projection card.

3. **No API-vs-subscription savings projection anywhere.**  New `<UsageWhatIfProjection>` card shows, per engine with a published API rate, your actual cost / API-equivalent cost / saved by plan / saved %.  MiniMax's row is the headline: Token Plan Max $55/mo vs MiniMax M3 PAYG equivalent.  Math pinned by `UsageWhatIfProjection.test.tsx` (1M-token MiniMax M3 fixture = $1.74).  Mirrored into the standalone Usage Monitor (`~/Code/Usage-Monitor`).

4. **Grok had no quota source.**  `grep -rEn 'grok.*quota' src/ server/` showed only a regex in `server/model-fallback.ts:37`.  New `server/grok-quota.ts` mirrors `server/antigravity-quota.ts` and returns an honest `method: "no-source"` snapshot with a populated reason (`The grok CLI does not expose a quota subcommand as of 2026-09-23`).  Wired through `server/index.ts` (`startGrokQuotaPoller()`, `lastGrokQuotaSnapshot()` on `/api/quotas`).  The Settings panel's Grok row renders a "no quota source available yet" line — no fabricated numbers.  When xAI ships a quota endpoint the swap is a single-file change.

5. **Capabilities inconsistency.**  `<MiniMaxCallout>` rendered a "Why this engine?" detail block for MiniMax only.  Replaced by shared `<EngineCallout>` mounted for every installed engine in both `EnginesSettings.tsx` and `ModelPicker.tsx`.  Plus a new `<EngineCapabilitiesMatrix>` rendering a 12×7 grid (capabilities × engines) with a `PricingModeChip` per column header and hover-to-surface prose.
